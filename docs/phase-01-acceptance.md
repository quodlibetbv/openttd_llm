# Phase 01 Acceptance Evidence

Phase 01 implements the setup-and-doctor objective in [`phases/PHASE-01-SETUP-AND-DOCTOR.md`](../phases/PHASE-01-SETUP-AND-DOCTOR.md).

| Requirement | Evidence |
|---|---|
| Repeatable Windows bootstrap | [`scripts/bootstrap.ps1`](../scripts/bootstrap.ps1) restores/builds, delegates repository state to the CLI, copies examples only when absent, and keeps normal OpenTTD/OBS profiles untouched. [`BootstrapServiceTests`](../tests/Arena.Foundation.Tests/BootstrapServiceTests.cs) proves re-running preserves local configuration. |
| Closed local contracts | [`schemas/setup/`](../schemas/setup/) contains local config, provider config, and doctor-report schemas with valid and invalid fixtures. [`ArenaConfigurationLoader`](../src/Arena.Orchestrator/ArenaConfigurationLoader.cs) rejects unknown fields, raw secret-shaped fields, non-loopback controls, and runtime path escape. |
| Credential safety | [`WindowsCredentialStore`](../src/Arena.Storage/WindowsCredentialStore.cs) scopes managed targets, uses Windows Credential Manager, and returns disposable secret material only for local authenticated operations. [`SecretRedactorTests`](../tests/Arena.Foundation.Tests/SecretRedactorTests.cs) covers output redaction. |
| Isolated runtime | [`RuntimeLayoutBuilder`](../src/Arena.Storage/RuntimeLayoutBuilder.cs) writes only below the repository-owned runtime, rejects junction traversal, excludes source profile/secrets configuration, copies ArenaGS/ModelProxyAI, creates OpenTTD 14-compatible generated configs, and writes a deterministic content manifest. [`RuntimeLayoutInspector`](../src/Arena.Storage/RuntimeLayoutBuilder.cs) verifies the generated loopback binding, listener ports, package metadata, and manifest hashes before doctor passes. |
| OBS readiness | [`ObsSceneTemplateGenerator`](../src/Arena.Obs/ObsSceneTemplate.cs) creates required scenes/source names; [`ObsWebSocketInspector`](../src/Arena.Obs/ObsWebSocketInspector.cs) authenticates WebSocket 5.x and reads scene inventory without modifying OBS. |
| Structured diagnosis | [`DoctorService`](../src/Arena.Orchestrator/DoctorService.cs) emits pass, warning, and blocking result records; [`ttd-arena doctor --json`](../src/Arena.Cli/ArenaCommandLine.cs) returns non-zero when any result is blocking. |

Windows 11 operational acceptance is complete. A clean native Windows test copy completed bootstrap twice with unchanged local-config and content-manifest hashes; doctor passed all host, dependency, runtime, package, path, disk, and port checks. Deliberate OpenTTD, OBS, credential, game-port, and AdminPort misconfigurations each produced their expected blocking diagnosis. The live dedicated OBS credential, WebSocket authentication, and scene-inventory check was operator-approved because its password must never be automated or placed in test inputs. Follow the exact Windows procedure in [`SETUP.md`](../SETUP.md#run-doctor) for future host verification; do not claim a game, AdminPort, provider, or recording smoke run from Phase 01.
